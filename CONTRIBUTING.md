# Contributing to YapFlow

Thank you for helping make private, local voice computing better.

## Before opening a pull request

1. Open an issue for substantial behavior or architecture changes.
2. Keep changes focused and avoid unrelated formatting.
3. Do not commit recordings, transcripts, credentials, installers, models, or
   other personal/generated files.
4. Run the web build, JavaScript tests, and Rust library tests documented in
   the README.
5. Explain the user-facing change, its privacy impact, and how you tested it.

Pull requests are reviewed by a maintainer before merge. Contributions do not
grant production, release-signing, Railway, domain, or package-publishing
access.

## Privacy principles

- Speech and meeting content stays on the device.
- New network activity must be disclosed and justified.
- Permission checks must read the operating system's real state.
- Features should continue to work without an account.
- Logs must not contain transcripts or secret material.
